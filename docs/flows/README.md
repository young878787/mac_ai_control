# flows 目錄：流程圖與結構圖的寫法規範

`docs/flows/` 放「程式怎麼跑」（流程檔）與「模組怎麼依賴」（結構檔）。決策見 [0027](../decisions/0027-flow-docs.md)；文件分工見 [0016](../decisions/0016-docs-structure.md)。規範中能機械判斷的部分由 `tests/unit/test_docs_flows.py` 檢查（T1～T11，見最後一節），跟著 `pytest -m unit` 一起跑。

| 檔案 | 類別 | 內容 | 章節字母 |
|---|---|---|---|

下一個可用的章節字母是 **L**。新增檔案或章節時同步更新這張表。

## 1. 何時要畫圖

- 跨模組、跨執行緒、有退回鏈，或有守門順序時一定要畫；單一函式的內部邏輯只寫文字。
- 圖或文字提到的函式、順序、退回鏈、守門一改，**同一個 commit 就要更新 flows**；計畫結案時也要同步。

## 2. 檔案

- 分兩類：
  - **流程檔**：一檔一條入口流程（`main-flow.md`、`slow-path.md`）。箭頭代表執行順序（見 4.3）。
  - **結構檔**：描述靜態結構（`module-deps.md`）。箭頭的意思寫在檔案開頭（例如「A import B」）；第 3 節的章節規則不套用。
- H1 寫成「名稱：一句話」。第一段寫範圍、相關 flows 與 ADR 連結，接著放總覽圖。
- 新增檔案時加進上面的表，寫明類別。

## 3. 章節（只套用在流程檔）

- 格式 `## <字母>. 標題`。字母在 `docs/flows/` 全域唯一、**只增不改**（其他地方會用「見 C.6」引用）；章節搬檔時字母跟著走。
- 每節標題後的前三行內要有 `階段：…`，直接對應紅線 1（比對階段不碰 IO）：
  - 比對階段（純函式）
  - 執行階段（`command_worker` 執行緒）
  - STT 執行緒、`ui-bus` 執行緒、計時器執行緒、桌面行程……
- 有相關 ADR 時寫 `決策見 [NNNN](…)`，可以和 `階段：` 放在同一行。

## 4. Mermaid

### 4.1 圖型

只用 `flowchart TD`；跨行程的協定往返才用 `sequenceDiagram`。

### 4.2 節點

- ID 用英文 PascalCase（例如 `FastPath`、`WeatherApi`），同一張圖內唯一；每個節點的標籤只定義一次，之後只寫 ID。
- 標籤一律加雙引號，換行用 `<br/>`，標籤裡不放 `"`。
- 形狀固定 4 種：

  | 用途 | 寫法 |
  |---|---|
  | 步驟、函式 | `Id["…"]` |
  | 判斷 | `Id{"…"}`（標籤寫判斷的對象或問句） |
  | 佇列、`STORE`、資料庫、清單 | `Id[("…")]` |
  | 外部服務（雲端、本機 LLM、Brave、氣象署、Open-Meteo、InnerTube） | `Id[["…"]]` |

- 結果節點以 ✅／⚠️／❌／⏭️ 開頭（紅線 11）。
- 守門與信任邊界（`_blocked`、`intent_guard`、`validate_calls`、`validate_tool_call`）出現在流程上時一定要畫成判斷節點。
- 識別字照程式碼原樣寫，不加反引號，方便 grep。

### 4.3 邊

| 寫法 | 意思 |
|---|---|
| `A --> B` | 同一句內的下一步 |
| `A -- "條件" --> B` | 分支；判斷節點的每條出邊都要有條件 |
| `A -.-> B`、`A -. "條件" .-> B` | 跨語句、計時器、背景執行緒 |

- 邊的條件一律加雙引號。
- 一行寫一條邊，或 `A --> B --> C` 這種鏈；不用 `&` 合併多個節點。
- 不用 `==>`、`---`、`--x`、`--o`、`-->|條件|`。

### 4.4 大小與樣式

- 一張圖最多 20 個節點，超過就拆成子節的圖。
- 不用 `subgraph`、`classDef`、`style`、顏色。

## 5. 文字

- 條列順序就是執行順序。
- 數值寫常數名，括號附目前的值，例如 `WAKE_SESSION_S`（60 秒）。這條只套用在新寫或改到的文字，舊文字改到時才換。
- 寫成 `模組.名稱`（例如 `actions.run_tool`）的識別字必須真的存在於該模組的頂層，改名時一起改文件。
