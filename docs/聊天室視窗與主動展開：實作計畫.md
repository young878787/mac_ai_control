# 聊天室視窗與主動展開（桌面角色 UI 擴充）

狀態：P0–P5 已實作（2026-11-18，基準 HEAD `5b0b088`，尚未 commit）。實作結果、與計畫的差異、尚未驗證的項目見 §10。

## 1. 要解決的問題

桌面角色的泡泡是「瞄一眼」用的，讀長內容、看細節都不夠：

| 項目 | 現況 | 位置 |
|---|---|---|
| 視窗 | 固定 360×560、不可縮放、透明置頂 | `desktop/main.js` `WIN_W／WIN_H` |
| 泡泡 | 最寬 300px、最多 3 行、同時最多 3 個、3～12 秒消失 | `renderer/style.css`、`state.js` `BUBBLE_*` |
| 結果摘要 | 回覆或最多 2 行 log，**超過 80 字截斷** | `state.js` `summarize` |
| 對話紀錄 | 畫面程序記憶體、50 筆、一行一筆純文字、**失焦或 Esc 就關** | `renderer/ui.js` `createHistory`、`renderer/app.js` |

後端的 `result` 事件其實有完整的 `replies`／`steps`（`assistant.result_event`），是前端截掉的。另外，前端沒辦法從現有欄位判斷「這句是看畫面或聊天」：`read_screen` 會記在 `ctx.calls`，但 `chat_reply` 不會，雲端的文字回覆是在 `slow_path._execute_cloud` 才決定要不要採用。所以「主動展開」需要後端明確標記。

## 2. 已定案的決策（2026-11-18 使用者確認）

| # | 決策 |
|---|---|
| D1 | 聊天室是**獨立視窗**（不是從角色視窗往旁邊展開） |
| D2 | 紀錄**只放記憶體**，重開 App 就清空；不寫硬碟 |
| D3 | **不做後台** |
| D4 | 點角色會彈出「快捷泡泡」，這次只做「💬 聊天室」一顆。點頭＝開始聆聽（`wake`）、點身體＝happy，這兩個原本的反應**保留** |
| D5 | 配色：**淺藍＋白底**，聊天室與角色視窗的泡泡都換 |
| D6 | 平常**不開**聊天室，只用泡泡 |
| D7 | 後端判斷要展開時，聊天室**主動帶動畫展開**。條件見 §4.1：看畫面、聊天、複雜功能（一句裡有 **2 個以上動作**，或回覆**超過 20 字**） |
| D8 | 主動展開後，如果滑鼠沒移上去、也沒點進去，**20 秒後自動收回**；有互動就一直開著，直到按 ✕ 或 Esc。手動打開的不會自動收 |
| D9 | Alt+Space 單行輸入框、多筆搜尋結果清單**留在角色視窗**，只換配色 |

## 3. 架構

```
後端 command_worker
  process_voice_command／process_choice
    └─ 結尾 expand_reason(ctx) → outcome["expand"]：screen／chat／complex／None
  result_event：新增選用欄位 expand；steps 每步新增選用欄位 route、ms
  command_record：commands.jsonl 一併記 expand（追查「為什麼開了」）
        │ ui_bus（協定不變，只多選用欄位；PROTOCOL_VERSION 維持 1）
        ▼
Electron 主程序 main.js（唯一持有匯流排連線與 token）
  ├─ 角色視窗（原有）：事件照轉
  ├─ chat.js（新，純邏輯、時間注入）：聊天紀錄＋聊天室開關狀態機
  │     handle(msg, now)／userCommand／tick(now)／hover／focus → 紀錄快照＋效果（open／close）
  └─ 聊天室視窗（新，啟動時先建好並隱藏）
        chat-preload.cjs 只開放：snapshot、send(command)、close、hover、focus
        送出一律經原本的 sendBus（ALLOWED_SEND 白名單）
```

純邏輯和 Electron 分開，做法跟 `state.js` 一樣，可以直接用 `node --test` 驗證。

## 4. 規格

### 4.1 展開判斷（後端，`pipeline.expand_reason`）

依優先順序取第一個成立的條件：

| 值 | 條件 | 判斷來源 |
|---|---|---|
| `screen` | 這句有 `read_screen` 執行成功（本機 VL 或雲端） | `ctx.calls` 的 (名稱, 參數, 成功) |
| `chat` | `chat_reply` 拿到模型回覆，或雲端的文字回覆被採用 | `ExecContext` 新增 `ai_reply: bool`，在 `actions.chat_reply` 成功、`slow_path._execute_cloud` 採用 `content` 時設定 |
| `complex` | 動作數 ≥ 2（`ctx.calls` 中**不含 `chat_reply`**，含失敗與 ⏭️ 略過），**或**回覆總字數 > 20 | 回覆總字數＝`sum(len(r.strip()) for r in ctx.replies)`，以 Unicode 字元計 |
| 不帶欄位 | 以上都不成立 | — |

`ExecContext` 不跨語句（§5.14），所以 `ai_reply` 和既有欄位一樣是同句狀態。

依現有程式碼推算，各種固定回覆的結果如下（P0 會實測）：

| 回覆 | 字數 | 結果 |
|---|---|---|
| `NO_ACTION_REPLY`「好，我沒有執行任何動作。」 | 12 | 不展開 |
| 例外「執行時發生錯誤」 | 7 | 不展開 |
| 多筆搜尋「找到 3 筆「報告」。說「第二個」或點選清單即可顯示」 | 27 | **展開**（清單仍在角色視窗，D9） |
| AI 不可用「⚠️ AI 服務無法使用（…），這句沒有處理：「…」」 | > 20 | **展開** |
| 找不到 `local_miss_reply` | > 20 | **展開** |
| 開 App、調音量、深色模式等單一動作（沒有回覆） | 0 | 不展開 |

### 4.2 協定（`result` 事件，只新增選用欄位）

```json
{"type": "result", "command": "...", "ok": true, "total_ms": 1234.5, "replies": ["..."],
 "steps": [{"kind": "slow", "text": "...", "status": "ok", "logs": ["..."], "route": "cloud", "ms": 980.1}],
 "expand": "chat"}
```

- 沒有展開時**不帶** `expand`，不是帶 `null`。舊前端會忽略不認得的欄位。
- `route` 只在 Slow 步驟有；`ms` 是每一步的耗時。兩者都已經寫進 `commands.jsonl`，不會多暴露資訊。
- `logs` 本來就會送給 UI，聊天室只是把它完整顯示出來。

### 4.3 聊天室視窗（`main.js`＋`renderer/chat.*`）

| 項目 | 規格 |
|---|---|
| 建立 | 啟動時建好、先隱藏（展開就不必等載入） |
| 外觀 | 白底、無邊框（標題列可拖曳）、圓角、可縮放（最小 320×400，預設 420×600）、置頂 `floating`、所有桌面都可見、不顯示在 Dock |
| 位置 | 貼在角色視窗左側，下緣對齊螢幕工作區底部（避開 Dock）；左側空間不夠就改放右側。只記住**大小**，位置每次跟著角色走 |
| 主動展開 | 用 `showInactive()`，**不搶焦點**，最前面的 App 必須不變（前景會決定 `front_action`、分頁、看畫面的對象） |
| 動畫 | 視窗先以目標大小 `showInactive()`，內容用 CSS 從靠角色那一角放大＋淡入（約 200 ms，`transform`／`opacity`，由合成器處理）；收起時淡出約 150 ms，再隱藏視窗。**直接採用原計畫的備案（CSS）**：視窗是透明的，不必每幀改視窗大小 |
| 收合 | ✕、Esc（聊天室有焦點時）、再點一次「💬 聊天室」快捷泡泡。主動展開的自動收回規則見 D8 |
| 內容 | 使用者的話放右邊、淺藍底，前面標來源（🎙️ 語音／⌨️ 打字）。助手的回覆放左邊、白底淺藍框：完整的 `replies`，不截斷；沒有回覆時顯示各步驟的 log。每一步的 ✅／⏭️／❌、路線（fast／本機／雲端）和耗時預設摺疊。處理中（`executing`）顯示「…」。聆聽中的 partial 顯示在底部，顯示條件和角色泡泡相同 |
| 輸入 | 多行輸入框：Enter 送出、Shift+Enter 換行、上限 `UI_COMMAND_MAX_CHARS`。送出走 `command` |
| 紀錄 | 放在主程序記憶體，最多 200 筆。聊天室關掉再開都還在；App 重開就清空（D2） |
| 安全 | 文字一律用 `textContent`；CSP 和角色視窗相同（不需要 pixi 的 `unsafe-eval`，可以拿掉）；檔案放在已開放的 `renderer/` 目錄，`resolveAppFile` 白名單不用改；`chat-preload.cjs` 不開放 `menu`、`drag`、`setIgnore` |

### 4.4 角色視窗（`state.js`、`renderer/*`）

- **快捷泡泡**：點角色時，原本的反應照舊，同時在頭部旁邊彈出快捷泡泡（現在只有「💬 聊天室」）。5 秒沒動作（滑鼠停在上面不計時）、按 Esc 或再點一次角色就收起來。**「點空白處」做不到**：角色視窗的透明區域是點擊穿透的，點下去的是底下的 App，視窗收不到事件。點「💬 聊天室」會開或關聊天室（手動開啟，不會自動收）。
- **收到帶 `expand` 的 result**：角色照常演出動作和表情，但泡泡改成短句「詳細內容在對話視窗」。泡泡種類維持 result 或 error，失敗時仍是珊瑚色邊框。
- **移除舊紀錄面板**：`createHistory`、`#history`、`toggle-history`、`HISTORY_MAX`。右鍵選單的「對話紀錄」改成「聊天室」（開或關）。`scripts/ui_demo.py` 和 `main.js` 的除錯鉤子 `PAGE_STATE` 也一併更新。
- **配色**（CSS 變數）：

| 變數 | 值 | 用途 |
|---|---|---|
| `--bg` | `#ffffff` | 泡泡、聊天室底色 |
| `--ink` | `#1f2a37` | 主要文字 |
| `--muted` | `#6b7c8f` | 次要文字 |
| `--sky` | `#6cc3f5` | 淺藍強調（成功邊框、標題列、焦點框） |
| `--sky-soft` | `#e3f3fd` | 使用者訊息底色、hover |
| `--coral` | `#f07a6a` | 失敗 |

  套用範圍：泡泡、快捷泡泡、Alt+Space 輸入框、搜尋結果清單、聊天室。會話光環（halo）**不改**。

## 7. 回退方式

- **後端**：`expand`、`route`、`ms` 都是選用欄位，回退前端後舊畫面會忽略它們；後端可以單獨保留或還原。
- **前端**：還原 `desktop/` 的變更即可。聊天室不寫任何持久資料；`settings.json` 只多一個聊天室大小，舊版會忽略。

## 8. 風險與已知限制

1. **20 字門檻很低**：大部分 AI 回覆、AI 不可用、找不到、多筆搜尋都會展開（§4.1 推算表）。P0 會量出實際比例，比例太高時回報，由使用者決定是否調整。
2. **「2 個以上動作」以實際執行的工具數計算**：如果某些單一說法在內部執行了 2 個工具，也會展開。P0 會列出這些句子。
3. **在聊天室打字時，最前面的 App 是本程式**：依賴前景的指令（例如「關掉這個分頁」）會退回預設對象（§5.16）。不會操作到錯的對象，但可能不是使用者預期的那個。
4. **原生動畫的順暢度**：`type: 'panel'`、置頂、無邊框、可縮放這些設定組合起來的效果要實機確認；不順就改用 CSS 動畫（P0 決定）。
5. **多一個常駐（隱藏中）的畫面程序**，會增加記憶體用量（R3 實測）。
6. **聊天室會完整顯示看畫面的描述**，可能包含螢幕上的敏感內容。只放在記憶體、不寫硬碟（D2），但視窗開著時旁人看得到。
