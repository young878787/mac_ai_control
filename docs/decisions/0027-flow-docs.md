# 0027 flows 文件規範：流程檔與結構檔、Mermaid 寫法、自動檢查

- 狀態：採用
- 日期：2026-11-26
- 來源：[計畫書](../plans/active/2026-11-26-import-linter-flows.md) §2、§4、§6；使用者 2026-11-26 的決定

## 背景

`docs/flows/`（[0016](0016-docs-structure.md) 第 1 條）原本只有兩份流程檔、6 張 Mermaid 圖，寫法沒有規範：標籤有的加引號有的沒有，外部服務、資料儲存和一般步驟同形狀，跨語句的邊有實線也有虛線，有兩節沒有章節字母，也沒有東西提醒文件裡的函式名稱已經過時。使用者要求把流向整理清楚。

## 決定

1. **規範寫在 [`docs/flows/README.md`](../flows/README.md)**（補充 0016 第 1 條的 `docs/flows/`），README 也列出所有檔案與已用掉的章節字母。
2. **檔案分兩類**：流程檔（一檔一條入口流程：`main-flow.md`、`slow-path.md`）與結構檔（`module-deps.md`，見 [0026](0026-import-linter.md)）。
3. **章節**（只套用在流程檔）：`## <字母>. 標題`，字母在 `docs/flows/` 全域唯一、只增不改；每節前三行內寫 `階段：…`（比對階段、執行階段、哪個執行緒），直接對應紅線 1。原本沒有字母的兩節改成 `J. 量測鏈`、`K. validate_calls`。
4. **Mermaid**：只用 `flowchart TD`（跨行程協定才用 `sequenceDiagram`）；節點 ID 用 PascalCase、標籤一律加引號；形狀固定 4 種（步驟、判斷、資料儲存 `[(…)]`、外部服務 `[[…]]`）；邊只用 `-->`、`-- "條件" -->`、`-.->`、`-. "條件" .->`，虛線表示跨語句、計時器、背景執行緒；判斷節點的每條出邊都要有條件；守門與信任邊界畫成判斷節點；結果節點以 ✅／⚠️／❌／⏭️ 開頭；一張圖最多 20 個節點。
5. **自動檢查** `tests/unit/test_docs_flows.py`（T1～T11）：只用標準庫，離線、毫秒級，跟著 `pytest -m unit` 跑。每項都有寫在測試裡的正例與反例。T9 檢查文件裡 `模組.名稱` 的識別字在該模組頂層存在；找到過時的識別字時修文件、不修程式。
6. **不自動檢查 Mermaid 能不能渲染**（要裝 mermaid-cli 與 Chromium，不加這個依賴）；改圖後在 GitHub 或裝了 Mermaid 擴充的 VS Code 預覽確認。

## 後果

- 改到流程（函式、順序、退回鏈、守門）的 commit 要同時更新 flows；T9 會抓到改名後沒跟著改的識別字，但抓不到語意過時（例如順序變了）。
- 新增流程章節要用下一個可用字母（目前是 L），並更新 README 的檔案表。
- T9 只認 `模組.名稱` 這種寫法；`step["web"]`、JSON 欄位不會被檢查。
