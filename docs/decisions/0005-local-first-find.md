# 0005 找東西本機優先，找不到才轉交模型

- 狀態：採用
- 日期：2026-11-08
- 來源：[本機優先的找東西分流](../plans/completed/2026-11-08-local-first-find.md) §2、§14、§15

## 背景

「找／打開／搜尋」原本直接交給 LLM 或網頁搜尋，常常把本機有的 App、專案、檔案拿去上網找。之後又發現「找工作」「找到了」這類句子被誤當成搜尋檔名。

## 決定

1. 兩層分離：第一層 `domain.resolve_intent` 判斷範圍（純函式），第二層 `local_actions` 只讀 `Intent.slots` 執行。範圍判斷順序固定：網頁範圍詞 → 專案 → 資料夾 → App → 即時資訊 → 檔案 → 預設。
2. 「找」「打開」本機優先；「搜尋」「查」只有帶範圍詞或命中專案時才走本機，其餘維持網頁搜尋。「找 + App 名稱」直接開 App。
3. 檔案預設只「在 Finder 中顯示」，使用者明說「打開」才開檔；危險副檔名與無副檔名的可執行檔一律只顯示。搜尋只限家目錄，排除 `~/Library`、隱藏資料夾、`node_modules`、`.app` 內部，以及符號連結逃出家目錄的結果。
4. 多筆結果列成清單（`choices.STORE`，60 秒 TTL），可說「第 N 個」或在桌面角色上點選。
5. 0 筆時：有本機證據（副檔名、範圍詞、位置、只說類型或時間）→ 回「本機沒有」；沒有證據 → 同一步轉交本機 LLM，查詢用使用者原話。前景是瀏覽器時直接站內／網頁搜尋，不問模型。轉交不碰雲端。

## 後果

- 判斷結果寫在 `step["intent"]`，錯判時從這裡追查。
- 調整範圍判斷只動 `domain.py`，要有 Intent 層的測試。
