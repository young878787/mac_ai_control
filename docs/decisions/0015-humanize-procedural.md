# 0015 擬人化：程序層接管頭身眼眉，用指標判定「無機械感」

- 狀態：採用（第 4 點「最後由使用者目視判定」被 [0018](0018-visual-checks-quantitative.md) 取代）
- 日期：2026-11-20
- 來源：[桌面角色擬人化](../plans/completed/2026-11-20-humanize.md) §0、§2 B1～B11、§12.3

## 背景

原生 Idle 動作會循環（閒置軌跡的自相關 0.98），眼睛一直盯著游標，看起來像機器。

## 決定

1. 只改 `desktop/`：後端、`ui_bus` 協定、模型檔都不動；不做聲音、TTS、口型（B1、B7）。
2. 程序層（`renderer/animation/` 的 mixer、ambient、face、procedural）接管頭、身、眼、眉；Idle 只保留手臂、肩、呼吸、嘴。反應動作播放時，程序層把頭身讓給動作（B2）。`PROCEDURAL=false` 可以退回舊做法。
3. 注意力導演 `domain/attention.js` 是純邏輯（情境 → 注視計畫，亂數注入）。游標明顯移動才看過去，停下 1.5～3 秒就失去興趣（B4）。
4. 無機械感指標（B3、B9）：頭部角速度 < 1°/s 的時間 ≤ 15%、最長靜止 ≤ 2 s、視線剛好在正中 0%、掃視 90% 到位的中位數 ≤ 90 ms、同一個 seed 逐幀可重現、閒置 5～40 s 延遲的最大自相關 < 0.5。最後由使用者目視判定。
5. CPU 沿用 [0013](0013-fullrig03-cpu-budget.md)：出場與進退場每秒峰值 ≤ 5.0%（整台電腦），潛伏停格平均 ≤ 0.125%（B5）。幀間隔 p95 與 RSS 以同機同狀態「不比改前差」判定（B11）。
6. 活潑動作（跳一下、哼歌搖擺、伸懶腰）等放第二版（B6）。

## 後果

- 指標定義與門檻在 `desktop/dev/motion-metrics.js`，不得為了過關放寬。
- 結案時留下 3 項接受現況的差異：出場峰值中位 5.15%（改前同時段 5.02%，分佈重疊）、p95／RSS 差異在雜訊範圍內、60 Hz 下掃視路徑掃過正中 2%（真實的 30 Hz 為 0%）。
