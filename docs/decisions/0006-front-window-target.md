# 0006 以前景視窗為對象；「按鈕」＝常用功能

- 狀態：採用
- 日期：2026-11-14
- 來源：[前景視窗上下文與常用功能](../plans/completed/2026-11-14-front-window-context.md) §2 D1～D5

## 背景

「搜尋 X」「開新分頁」「關掉這個」這類句子的對象是目前的視窗。原本一律用預設對象（Google、Safari），不符合使用者的預期。

## 決定

1. 對象的優先順序固定：**句子明說的 → 同句剛開的（`last_browser`／`last_editor`）→ 前景視窗 → 預設**。前景讀不到（包括桌面角色自己在前景）就退回預設，不猜。
2. 停在已知網站時，「搜尋／查 X」直接用站內搜尋；句子有即時資訊詞或網頁範圍詞時仍走 Google（D1）。
3. 編輯器在前景時，「開終端機」開內建終端機；明說「終端機程式／Terminal」才開 Terminal.app（D3）。
4. 「按鈕」指各 App 的常用功能（詞庫 `app_shortcuts`），不做「按下畫面上某個名稱的按鈕」，桌面角色也不加按鈕（D4）。
5. 前景只在執行階段讀，而且用到才讀：只需要 App 時用 `lsappinfo`（約 11 ms）；瀏覽器網址用 `osascript`（Safari 約 170～230 ms），只在站內搜尋與需要網站的快捷鍵時才問。`match()` 與 `completeness` 不得讀前景。

## 後果

- 端雲協同計畫據此刪掉「本機看畫面點 UI」（V 類）。
