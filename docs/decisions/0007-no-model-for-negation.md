# 0007 否定或敘述句不呼叫任何模型（G1）

- 狀態：採用
- 日期：2026-11-15
- 來源：[前景視窗上下文與常用功能](../plans/completed/2026-11-14-front-window-context.md) §15 D10～D12；端雲 K4

## 背景

Fast Path 守門（`_blocked`、`_QUESTION_RE`）把否定、敘述、提問句交給 LLM 判斷，但 4bit 模型幾乎不理會否定。實測 30 句 × 3 次：真否定只有 3/33 正確，敘述 3/18；63 次不該動作中有 27 次是睡眠、鎖定、關閉 App（「別讓電腦睡眠」→ 睡眠）。chat 回覆還會謊稱已執行（19 句 × 3 次中有 7 句）。改提示詞也無效。

## 決定

1. `slow_path.intent_guard`：任一子句是否定或敘述 → 不呼叫任何模型（本機、雲端、規劃、chat 都不送），回固定文字 `NO_ACTION_REPLY`。
2. 每個子句都是資訊提問（什麼、怎麼、為什麼…）→ 照常規劃，但執行前丟掉會改變狀態的 `STATE_TOOLS`。只有「嗎」的是非問句或客氣請求不擋；糾正句開頭的「沒有／不是／不對」不算否定。
3. 常見的「否定即指令」改成 Fast Path 窄規則 `_r_negated_command`，放在 `_blocked` 之前：「不要靜音了」「螢幕不要那麼亮」「不想用深色模式」。
4. 「剛剛開的關掉」會被當成敘述擋下，這是安全決策，不為代名詞放寬（[0009](0009-cloud-optional.md) 的對象守門另外處理「它」）。
5. 例外（2026-11-23，[0021](0021-weather-answer.md)）：天氣問句（「今天台北會下雨嗎」）走 Fast Path 窄規則直接回答，只豁免「提問」這一關；否定、敘述仍照第 1 條擋下。

## 後果

- 寧可少做：混合句只要有一個子句是否定，整步就不動作。
- 放寬任何守門之前，先列出誤觸發案例並實測。
