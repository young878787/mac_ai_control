# 桌面角色介面與喚醒會話

狀態（2026-11-05）：Phase 0～5 已實作；自動化測試全數通過；真實環境驗收部分完成（結果見 §13）。**E8 效能有兩項未達提議門檻，需要使用者決定**（§13.3）；語音端到端（E1、E9）與桌面空間／全螢幕（E6）等尚未驗證。

## 1. 要解決的問題

| 問題 | 現況 |
|---|---|
| 只能看終端機 | 所有狀態、辨識文字、執行結果都是 `print`；沒有畫面可看助手在做什麼 |
| 只能用語音或 `--text` 下指令 | 執行中不能臨時打字 |
| 喚醒詞每句都要喊 | `WakeGate` 只說喚醒詞後，8 秒內的**下一句**免喚醒詞，用一次就結束 |

目標：Rushia（Live2D）常駐在螢幕右下角，平常從下緣探頭；被喚醒時出場、依助手狀態做動作、以泡泡顯示文字；可用快捷鍵叫出輸入框打字；喚醒一次後 60 秒內免喚醒詞、每句重新計時。

## 2. 已定案的決策

| 項目 | 決定 | 來源 |
|---|---|---|
| 桌面殼 | Electron | 使用者確認 |
| 畫面寫法 | 原生 ES modules（沿用 `Rushia_hd/preview` 的寫法），**不加 React／Vite** | 建議，待確認（§10-1） |
| 會話長度 | 60 秒，每句重新計時 | 使用者確認 |
| UI 模式的喚醒詞 | `--ui` 預設**開啟**喚醒詞；終端機模式維持 `WAKE_WORD_ENABLED = False` | 使用者確認 |
| TTS／嘴型 | 不做 TTS，也不做假嘴型；不使用 `Talk` 動作 | 使用者確認 |
| 停靠位置 | 主螢幕右下角，從下緣探頭；試用後再調 | 使用者確認 |
| 角色走路 | 不做：模型沒有走路動作（模型本身有腿與鞋，預覽只是裁在大腿；2026-11-05 實作時更正原先「沒有腿」的說法）；出場用「從下緣滑上＋回彈」 | 沒有對應動作 |
| 參考對象 | Mate-Engine（Unity＋VRM、AGPL＋自訂授權）只參考互動設計，不沿用程式與素材 | — |

**為什麼不用 React／Vite**：Electron 是視窗殼，React／Vite 是畫面的寫法與打包工具，兩者不是二選一。這次畫面主體是 pixi 的 canvas（命令式更新參數），DOM 元件只有泡泡、輸入框、紀錄面板三種，React 帶來的好處小，卻多一層依賴與打包步驟；預覽程式已證明不打包也能跑。之後若要加設定頁等較多表單，再引入 Vite。

## 3. 架構

```
Python 後端（main.py --ui）                               Electron（desktop/）
 mic → STT → CommandRouter ──┬─▶ WakeGate（會話）          ┌─ main.js：透明視窗、穿透切換、快捷鍵、
                              │                            │           游標座標、右鍵選單、logs/ui.jsonl
        指令佇列 ◀────────────┤                            │
          │                   │  ws://127.0.0.1:8766       └─ renderer：pixi＋Live2D、狀態機、
          ▼                   └─▶ UiBus ◀════════════════════▶            泡泡、輸入框、紀錄面板
   command_worker ─ result ──▶ （publish，非阻塞）  ◀── command／wake／pause／quit
```

- 事件只在 `assistant.py` 這層發出；`router/`、`stt/` 不改（`completeness.classify` 只是改由呼叫端傳入喚醒詞開關）。
- 不加 `--ui` 時不建立 UiBus、不啟動 Electron，行為與現在完全相同。
- 生命週期：`main.py --ui` 啟動 Electron 子程序並負責收掉；使用者從右鍵選單「結束」→ Electron 送 `quit` → 後端走既有的 Ctrl+C 收尾流程。Electron 意外結束時後端印出警告、繼續語音運作，不自動重啟 UI。

## 4. 事件協定 v1（JSON over WebSocket）

連線：由 Electron **主程序**（Node 內建 WebSocket，不帶 Origin）持有並把事件轉給畫面程序，token 不進畫面程序；只綁 `127.0.0.1:8766`；URL 帶一次性 token（`?token=…`，每次啟動隨機 32 bytes，透過環境變數交給 Electron）；token 不符或帶有 `http(s)://` 的 `Origin` 標頭一律拒絕。原因：任何網頁都能對 `ws://127.0.0.1` 發連線，不擋的話網頁可以送 `command` 執行關機等動作。

**後端 → UI**（每則都有 `type`、`id`（遞增序號）、`ts`（`time.time()`））

| type | 欄位 | 時機 |
|---|---|---|
| `hello` | `version: 1`、`wake_enabled`、`session_s`、`paused` | 連線建立時 |
| `partial` | `text`、`wake`（句首是喚醒詞） | STT partial |
| `heard` | `text`、`status`（command／armed／ignored）、`command` | 每句 final 過完閘門 |
| `session` | `remaining_s`（0＝結束） | 會話開始、延長、被 UI 結束或暫停時 |
| `executing` | `command` | 指令開始執行 |
| `result` | `command`、`ok`、`steps`（kind／text／status／logs）、`replies`、`total_ms` | 指令執行完；`ok`＝沒有任何一步是 `exec_failed`／`llm_unavailable`／`llm_error` |
| `stt` | `state`（connected／disconnected／error）、`message` | STT 連線事件 |
| `paused` | `value` | 暫停狀態改變 |

**UI → 後端**

| type | 欄位 | 處理 |
|---|---|---|
| `command` | `text`（去頭尾空白後 1～200 字） | 直接放進指令佇列，不經喚醒詞閘門（同 `--text`）；不影響會話計時 |
| `wake` | — | 開啟／延長會話（點角色頭部） |
| `pause` | `value` | 暫停時 final 一律丟棄並結束會話；音訊仍照常送 STT |
| `quit` | — | 後端結束 |

不合格的訊息（非 JSON、未知 type、字數超出）丟棄並在終端機印警告，不中斷連線。`publish()` 為非阻塞：每個 client 一個上限 256 則的佇列，滿了丟最舊的。

## 5. 喚醒會話規則（`mac_ai/wake.py`）

`WAKE_WINDOW_S = 8.0` 改為 `WAKE_SESSION_S = 60.0`，語意由「一次性待命」改為「滑動會話」：

| 輸入 | 會話外 | 會話中 |
|---|---|---|
| 喚醒詞＋指令 | 執行指令，開啟會話 | 去掉喚醒詞後執行，重新計時 |
| 只有喚醒詞 | `armed`，開啟會話 | `armed`，重新計時 |
| 無喚醒詞的句子 | `ignored` | 執行，重新計時 |
| 空白／只有標點 | `ignored` | `ignored`，**不**重新計時 |

- 計時起點＝`feed()` 收到這句的時間（不是指令執行完的時間）；距起點 ≤ 60.0 秒仍在會話中（沿用現在的 `<=`）。
- 新增 `start_session()`、`end_session()`、`session_remaining()`，給 UI 的 `wake`／`pause` 與 `session` 事件使用。UI 依 `remaining_s` 自行倒數，後端不另開計時執行緒。
- 停用喚醒詞（`enabled=False`）的行為完全不變。
- 終端機訊息改為「👂 已喚醒，60 秒內不用再說喚醒詞（每句重新計時）」。
- 這是**有意的行為變更**，影響喚醒詞開啟時的終端機模式；需改寫的既有測試（實際為 5 處加參數更名，比原先列的多一處）：`test_wake_word_only_arms_then_next_sentence_executes_once`、`test_armed_window_boundary`、`test_wake_word_with_command_while_armed_strips_wake_word_and_ends_standby`、`tests/test_assistant_offline.py` 的 `window_s=` 參數名稱與 `test_wake_word_only_announces_standby_then_next_sentence_is_queued`、`test_voice_loop_end_to_end`（事件順序：未喚醒的句子要排在第一個喚醒之前，否則已在會話中會被執行）。
- `--ui` 時，`WakeGate(enabled=True)` 與 `EndpointDetector(classifier=partial(classify, wake_enabled=True))` 一起切換，避免端點判斷與閘門對喚醒詞的認定不一致。已知：只說「露西婭」時 `classify` 回 INCOMPLETE，靜音要等 2.0 秒才收句；為了讓角色不顯得遲鈍，UI 看到 `partial.wake == true` 就先出場（只做演出，不執行任何事）。

## 6. 角色演出

模型：`Rushia_hd/runtime-swing/RushiaHD.model3.json`（moc3 v5，需 Cubism 5 Core；4 張 4096 貼圖）。

| UI 狀態 | 進入條件 | 動作 | 表情 | 其他 |
|---|---|---|---|---|
| 潛伏 | 啟動；退場條件成立 | Idle | neutral | 只露出模型高度的 30%（`PEEK_RATIO`，提議值），15 fps |
| 出場 | `partial.wake`、`heard.armed`、點擊頭部、快捷鍵、收到 `executing` | Surprised 一次 → Idle | happy 2 秒 → neutral | 從下緣滑上 600 ms（ease-out-back），30 fps |
| 聆聽 | 會話中收到 `partial` | Idle | neutral | 泡泡即時顯示 partial；視線回正 |
| 執行中 | `executing` | Curious | neutral | 泡泡「…」 |
| 成功 | `result.ok` | Nod | happy 2 秒 | 泡泡顯示結果摘要；有 `replies` 則顯示回覆 |
| 失敗 | `!result.ok` | Shake | pout 2 秒 | 泡泡顯示錯誤摘要 |
| 會話結束 | 倒數到 0 | — | sleepy 1.5 秒 | 之後退場 |
| 退場 | 會話結束；非會話觸發（打字、點擊）時最後一個事件後 15 秒 | Idle | neutral | 滑回下緣 800 ms；輸入框或紀錄面板開著時不退場 |

- `heard.ignored`（未喚醒）不做任何演出，避免旁人講話讓角色一直亂動。
- 會話中頭上顯示光環＋倒數環（剩餘比例）。
- 不使用 `Talk` 動作；其他動作內的嘴部曲線（Happy 0.15、Surprised 0.28、Curious 0.05）屬於表情，保留。
- 泡泡：最多同時 3 則，顯示時間＝clamp(3 s＋0.15 s × 字數, 3 s, 12 s)（提議值），滑鼠停在泡泡上時暫停淡出。
- 互動：
  - 點擊頭部 → 出場＋送 `wake`；點擊身體 → Happy。
  - 拖曳只沿下緣水平移動（保持「從下緣探頭」成立），位置存在 Electron `userData/settings.json`。
  - 出場時視線跟隨游標：main 程序 30 Hz 讀 `screen.getCursorScreenPoint()`，`ParamAngleX` ±30、`ParamAngleY` ±20、`ParamEyeBallX/Y` ±1，每幀 lerp 0.15。
  - 右鍵選單：對話紀錄／暫停聽指令（勾選）／結束。
- 輸入框：`⌥Space`（可在 `settings.json` 改）叫出，位於角色下方；收音時 partial 以灰色 placeholder 顯示；Enter 送出 `command`、空白 Enter 或 Esc 關閉。
- 紀錄面板：半透明，保留最近 50 筆（heard、結果摘要、回覆），只存在記憶體；Esc 或點外面關閉。

## 10. 待確認

1. 畫面寫法：原生 ES modules，不加 React／Vite（理由見 §2；使用者回覆「用 Electron」，已照此實作）。
2. 會話結束詞（例如「沒事了」）：使用者這次沒提，**本計畫不做**；要的話另加規則與測試。
3. 提議值：`PEEK_RATIO` 0.3、視窗 360 × 560、泡泡 3～12 s、非會話退場 15 s、E2 的 50 ms、E8 的 CPU 3%／15%、RSS 700 MB、幀時間 34 ms。
4. 互動行為：點擊頭部開啟會話；拖曳只沿下緣水平移動；未喚醒的句子不做演出。

## 11. 風險與已知限制

- **Cubism Core 授權**：Live2D 專有授權，不入版控、不散布；個人使用沒問題，若要公開發佈需另看授權條款。
- **模型權利**：Rushia 為他人角色，模型僅限個人使用，`Rushia_hd/` 不入版控。
- **GPU 記憶體**：4096 貼圖 ×4 約 256 MB；桌寵尺寸用不到這麼高解析度，E8 不過時改輸出 2048 版。
- **`type: 'panel'` 的焦點行為**依 Electron 版本而異，E5 是確認方式；不過時要改成輸入時暫時變成一般視窗、關閉後用 `app.hide()` 交還焦點。
- **會話期間誤觸發**：60 秒內旁人講話或影片聲音會被當指令；以光環＋倒數讓狀態看得到，`pause` 可立即結束。
- **只說喚醒詞要等 2.0 s 才收句**（§5）；靠 `partial.wake` 提前出場掩蓋，實際執行時間不變。
- **依賴**：新增 npm 的 `electron`、`pixi.js`、`pixi-live2d-display`（只在 `desktop/`）；Python 端不新增依賴（`websockets` 已有）。

## 12. 回退方式

- UI：不加 `--ui` 即完全回到現有行為；`desktop/` 可整個刪除。
- 喚醒會話：Phase 0 是獨立 commit，`git revert` 即回到一次性待命（8 秒）。

### 13.3 E8 效能（需要使用者決定）

最終量測（30 秒取樣；Electron 4 個程序合計）：

| 項目 | 門檻（提議值） | 實測 | 結果 |
|---|---|---|---|
| 潛伏 CPU | ≤ 3% | **6.8%**（潛伏 5 fps） | **FAIL** |
| 出場（會話中、靜止）CPU | ≤ 15% | 13.6%（12 fps） | PASS |
| RSS 合計 | ≤ 700 MB | 574 MB | PASS |
| 動畫幀間隔 p95 | ≤ 34 ms | **34.3 ms**（中位 33.3；283 幀） | **FAIL（差 0.3 ms）** |

調校過程與發現：

- 最大的固定成本是 PixiJS 6 的 `InteractionManager` 掛在 `Ticker.system`，讓 rAF 永遠以 60 Hz 空轉；全部 ticker 停掉後，幾乎不畫幀時總 CPU 從 6.8% 降到 1.9%。
- 之後每一幀約 1.3% CPU／fps（模型只有 58 個 drawable，繪製與物理在畫面程序裡每幀僅約 2 ms；成本主要是 Electron 在 macOS 合成透明視窗與出幀）。關閉抗鋸齒、降解析度、關 `preserveDrawingBuffer`、mipmap、縮小遮罩緩衝都**沒有**影響；`use-angle=gl` 在這台機器上 GPU 程序初始化失敗，不可用。
- 所以只剩調幀率：動作／進退場中 30 fps、出場靜止 12 fps、潛伏 5 fps。**潛伏 ≤ 3% 約等於 1 fps，幾乎是靜止畫面**；要維持呼吸、眨眼的動態，我認為 3% 達不到。
- 幀間隔 p95 34.3 ms 是 vsync 對齊的抖動，門檻 34 只留了 0.7 ms 餘裕，我認為門檻太緊而非畫面有問題。

**請決定**：(a) 潛伏門檻改為多少（例如 ≤ 8%），或接受更低的潛伏幀率（1～2 fps，角色近乎靜止）；(b) 幀間隔 p95 門檻改為 ≤ 40 ms 是否可接受。我沒有自行改門檻。

### 13.5 與計畫的差異與實作時的發現

1. **模型有腿**：原先說「模型只到大腿、沒有腿」是錯的，預覽只是把畫面裁在大腿；出場時看得到全身與鞋子。仍沒有走路動作。
2. **WebSocket 由 Electron 主程序持有**，不是畫面程序（token 不進畫面、也不會被畫面程序的 Origin 擋下）。
3. **Cubism Core**：手上只有 6.x（來自 `AI_VT_V2`，沒有 5.x）。Core 6 把繪製順序從 `drawables.renderOrders` 搬到 `Model.getRenderOrders()`，pixi-live2d-display 0.4.0 讀不到，所以 `desktop/renderer/app.js` 有一個相容層 `bridgeRenderOrders`（模型含 offscreen 時直接拒絕載入）。渲染結果已與預覽圖目視比對一致；預覽程式原本限定 5.x，這裡放寬為 ≥ 5。若之後要換回 5.x，不需要改程式。
4. **`ELECTRON_RUN_AS_NODE`**：從 VS Code 等 Electron 程式的終端機啟動時環境裡有這個變數，Electron 會變成純 Node 而立即結束；`ui_service` 啟動時會移除它（有測試）。
5. **`npm install` 沒有下載到 Electron 執行檔**，要補跑 `node node_modules/electron/install.js`（README 已寫）。
6. 三段幀率（30／12／5 fps）與「事件到達立即補一幀」；高幀率用 rAF 逐 vsync 輪詢、低幀率用計時器，間隔最穩。
7. 新增開發用工具：`scripts/ui_demo.py`（示範、`--capture` 截圖、`--focus-test`、`--interact-test`）、`scripts/ui_perf.py`；Electron 端有只在設了 `MAC_AI_UI_CAPTURE_DIR` 時才生效的 `debug_*` 鉤子（截圖、切換輸入框、注入點擊、提交輸入），正式執行時後端送來也不處理。
8. `--ui` 與 `--no-stt` 併用時只會啟動 LLM 並等待，不會顯示桌面角色（`--no-stt` 的流程早於 UI 啟動）。
9. 還沒做、之後可補：結束詞、多螢幕、打包。
